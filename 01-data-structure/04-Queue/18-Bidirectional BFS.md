# Bidirectional BFS

#### 1. Definition — Must Know

1. **Bidirectional BFS** runs BFS from the **start** and from the **target** at the same time, until the two searches **meet**.
2. It needs a known target and moves that can be reversed (an undirected graph, or a way to go backwards).
3. It explores far fewer nodes than one-sided BFS when the graph branches a lot.

#### 2. Why It Is Used — Must Know

1. One-sided BFS visits about `b^d` nodes (`b` = branching factor, `d` = distance). Bidirectional visits about `2 · b^(d/2)`.
2. Example: `b = 10`, `d = 6`: `10^6 = 1,000,000` vs `2 · 10^3 = 2,000`.
3. It turns huge searches (Word Ladder with a large dictionary, puzzles) into fast ones.

#### 3. How It Works — Must Know

```text
One-sided:       start ●─────────────────────────────● target       (big circle around start)

Bidirectional:   start ●───────────●●───────────● target            (two small circles that meet)
```

Word Ladder, `hit → cog`, words `hot, dot, dog, lot, log, cog`:

```text
front = {hit}                 back = {cog}
expand the smaller side (front):  {hot}                  steps 2
front = {hot}                 back = {cog}
expand front:  {dot, lot}                                steps 3
front = {dot, lot} is bigger than back {cog} → swap, expand back:
back side: cog → dog, log                                steps 4
now front {dot, lot}  and  new {dog, log}: dog is a neighbour of dot → they MEET

answer = 5
```

Tip: always **expand the smaller frontier**. It keeps the work small.

#### 4. Core Concepts — Must Know

1. **Two frontiers** (as sets): `front` (from the start) and `back` (from the target).
2. **Two visited sets** (or one shared set). The search ends when a neighbour of the front is already in the back set.
3. **Expand one whole level at a time**, always from the smaller frontier.
4. **Steps** count levels from both sides together.
5. **Moves must be reversible.** In a directed graph, the backward search needs reversed edges.
6. **Use sets for frontiers**, because you need fast "is it in the other side?" checks.
7. **Not for weighted graphs** (unless you use bidirectional Dijkstra, which is more complex).
8. **Works with implicit graphs** (words, puzzle boards): neighbours are generated by rules.

| | One-sided BFS | Bidirectional BFS |
|---|---|---|
| Nodes visited | `~ b^d` | `~ 2 · b^(d/2)` |
| Needs a target | no | **yes** |
| Moves reversible | not needed | **needed** |
| Code | simpler | longer |

#### 5. Algorithm — Must Know

```text
front = {start}; back = {target}; visited = {start, target}; steps = 1
while front and back are not empty:
    if front.size > back.size: swap(front, back)
    next = {}
    for each node in front:
        for each neighbour of node:
            if neighbour in back: return steps + 1       // the searches met
            if neighbour not visited: visited.add(neighbour); next.add(neighbour)
    front = next
    steps++
return not found
```

#### 6. Kotlin Implementation — Must Know

```kotlin
// Word Ladder with bidirectional BFS (LeetCode 127): number of words in the shortest chain
fun ladderLength(beginWord: String, endWord: String, wordList: List<String>): Int {
    val words = wordList.toHashSet()
    if (endWord !in words) return 0
    words.remove(beginWord)
    words.remove(endWord)                         // the word set is also the "unvisited" set

    var front = hashSetOf(beginWord)
    var back = hashSetOf(endWord)
    var steps = 1

    while (front.isNotEmpty() && back.isNotEmpty()) {
        if (front.size > back.size) {             // always expand the smaller side
            val temp = front; front = back; back = temp
        }
        val next = HashSet<String>()
        for (word in front) {
            val chars = word.toCharArray()
            for (i in chars.indices) {
                val original = chars[i]
                for (c in 'a'..'z') {
                    if (c == original) continue
                    chars[i] = c
                    val candidate = String(chars)
                    if (candidate in back) return steps + 1       // the two searches met
                    if (words.remove(candidate)) next.add(candidate)
                }
                chars[i] = original
            }
        }
        front = next
        steps++
    }
    return 0
}

// Generic undirected graph, shortest distance between two nodes
fun bidirectionalDistance(graph: List<List<Int>>, src: Int, dst: Int): Int {
    if (src == dst) return 0
    var front = hashSetOf(src)
    var back = hashSetOf(dst)
    val visited = hashSetOf(src, dst)
    var distance = 0

    while (front.isNotEmpty() && back.isNotEmpty()) {
        if (front.size > back.size) { val t = front; front = back; back = t }
        distance++
        val next = HashSet<Int>()
        for (node in front) {
            for (neighbour in graph[node]) {
                if (neighbour in back) return distance
                if (visited.add(neighbour)) next.add(neighbour)
            }
        }
        front = next
    }
    return -1
}
```

Check: `ladderLength("hit", "cog", [hot, dot, dog, lot, log, cog])` → `5`. If `cog` is missing from the list → `0`.

#### 7. Time & Space Complexity — Must Know

| Approach | Time | Space |
|---|---:|---:|
| One-sided BFS | `O(b^d)` | `O(b^d)` |
| **Bidirectional BFS** | **`O(b^(d/2))`** | `O(b^(d/2))` |
| Word Ladder (`n` words, length `L`) | about `O(n · L · 26)` worst case, much less in practice | `O(n · L)` |

In the worst case (a graph with little branching, such as a path) the benefit is small.

#### 8. Common Bidirectional Patterns — Must Know

1. **Word Ladder** (LeetCode 127).
2. **Open the Lock** (LeetCode 752) — both ends known (`0000` and the target).
3. **Minimum Genetic Mutation** (LeetCode 433).
4. **Sliding Puzzle** (LeetCode 773) — start board and goal board.
5. **Shortest path between two people** in a social graph (degrees of separation).
6. **Knight shortest path** on a large board (LeetCode 1197, premium).
7. **Android example:** route search between two screens in a very large navigation or link graph.

#### 9. Edge Cases / Common Mistakes

1. Checking "met" only when removing from the queue. Check when **generating** a neighbour.
2. Not swapping to expand the smaller frontier, so the speed-up is lost.
3. Off-by-one in `steps` (whether a count means words or moves).
4. Not removing visited words, so frontiers grow forever.
5. The end word missing from the word list (answer `0`).
6. Start equals target.
7. Using it when moves are one-way and you did not build reverse edges.
8. Forgetting to put the target into the back set at the start.
9. Mixing the roles of `front` and `back` after the swap. The answer does not depend on which side is which, but the code must treat them symmetrically.

#### 10. When to Use / When Not to Use

**Use when:**

1. Both the start and the target are known.
2. The branching factor is high and the distance is large.
3. Moves are reversible.

**Avoid when:**

1. The target is unknown (search for "any goal" or "all nodes").
2. The graph is weighted or directed with no easy reverse.
3. A normal BFS is fast enough. It is simpler.

#### 12. Interview Must Remember

1. **Search from both ends, expand the smaller frontier, stop when they meet.**
2. About `b^(d/2)` instead of `b^d`.
3. Needs a known target and reversible moves.
4. Check for the meeting when you generate a neighbour.
